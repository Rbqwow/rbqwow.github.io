## 前情提要

开学前几天实在是受不了家里之前不知道谁什么时候买的，没有 WiFi6，不支持 IPv6，光猫桥接拨号一天断一百次重拨还慢的 TP-Link 路由器，加上小米 AX3000T 已经 179 三个多月了，八成是等不到更低价，于是直接京东下单次日达，京东还给了 51 块钱的优惠，到手价 127。

因为这个路由器是要放在家里用的，所以最开始为了稳定并没打算要刷 OpenWRT。但在折腾 WOL 时，发现小米这个固件并不像 TP-Link 那样，IP/MAC 绑定并不是写 ARP 表，所以在电脑关机之后完全不能通过公网 WOL 唤醒，但开机时又能接到包。于是找群友要到了闭源 QWRT 固件，翻了一堆教程，准备开刷。

小米 AX3000T 还算是款性价比不错的路由器，用的是联发科 MT7981 的解决方案，储存 128MB，内存 256MB。现在用的 QWRT R24.1.24 闭源固件对硬件驱动的支持还不错，稳定性目前刚跑了五天，没重启没出过任何问题，拿来当主路由完全够用。

毕竟是第一次折腾，结果还算不错，但是过程确实有点难受，一共熬了两天晚上，踩了一堆坑，遂开篇文章写一写。

## kengkengkeng

### 1. 卡降级

本来是没打算刷 OpenWRT 的，所以拿到手直接更新到了最新固件，结果想要刷的时候发现只能用旧版固件开 SSH。

在 OpenWRT 官网找到了[设备页面](https://openwrt.org/inbox/toh/xiaomi/ax3000t)，跟着给出的降级操作走，结果却提示固件损坏，尝试了数次，确认是漏洞已经被修复了。

最后用搜索引擎翻了翻，找到了小米路由器的修复工具，可以强刷指定固件，成功降级到了 1.0.47.

### 2. 刷错 uboot

因为要刷的是 QWRT，就没跟着官网给的步骤走，进入 SSH 备份完所有分区就刷了 [uboot](https://cmi.hanwckf.top/p/mt798x-uboot-usage/)。但我刷的不是带 `multi-layout` 的 uboot，而是那个 repo release 里最新的 uboot，并没有 `multi-layout`。所以刷完 uboot 刷 QWRT 的时候，虽然提示刷入成功，但路由器会一直重启，明显出了问题。

刷错 uboot 是我之后才知道的事，那时我还不知道可以用 uboot 刷 uboot。找 OpenWRT 官方固件刷也没用，刷 ImmortalWrt 也没用，想进 uboot 的 shell 也进不去，于是完全懵逼了半个多小时。直到翻到了上面那篇文章，知道了可以用 uboot 刷 uboot，于是刷了旧一个版本的 release，切换到 QWRT 分区布局后成功刷入 QWRT。

### 3. 插错网口

小米 AX3000T 的官方固件是支持 WAN/LAN 混插的，但 QWRT 不支持，好巧不巧的，我的电脑刚刚好插在了 QWRT 预设的 WAN 口上，于是又懵了一会才重新插了一遍网线，成功进入后台。

### 4. PPPoE 拨号和 IPv6

初始引导填写的 PPPoE 账密会自动填写在接口 WAN 和 WAN6，但默认接口 WAN 在 PPPoE 拨完号之后直接就有双栈了，并不需要 WAN6 再拨一次，也不需要把 WAN6 改成 DHCPv6。在`状态→概览→网络`中，IPv4 WAN 状态的节点类型是 `pppoe`，IPv6 是 `dhcpv6-pd`。

网上还有很多说 IPv6 应该怎么怎么配置，关闭内置的 IPv6 管理然后改这改那之类的，但我这直接就可以用了，局域网 IPv6 给每个设备同时分配公网和私有 IP，没有任何问题。

### 5. 多拨

在上面我提到了初始引导会让两个接口同时 PPPoE 拨号，也就是这时候我发现，路由器竟然同时拿到了两个公网 IPv4 地址，直接让我想到了多拨叠加网速的可能性。于是我找到了多线多拨&负载均衡的软件包，开始折腾。

神奇的是，成功了。在一号单线的情况下，我测试了双拨和三拨，都可以正常运行，并获取到对应数量的公网 IPv4 地址和 IPv6 网段。使用花瓣测速进行测试，下载可以跑满千兆网口，上传速度不稳定，但轻松超过了 100Mbps 甚至 300Mbps，总之非常震撼。

不过我并没有开这东西，一是为了防止被运营商找上门，二是没什么大用处。本来家里的宽带速度已经完全超过了家人的需求，而多拨多 IP 的上传也救不了 P2P 传文件的速度，索性测试完就关掉了。

有趣的是，在关闭多拨之后，局域网下的设备无法通过 IPv6 访问互联网了，但 IP 地址的获取完全正常。一番排查之后，发现是负载均衡的配置出了问题，Reject 了所有通过互联网的包。将`网络→负载均衡→策略→Balanced`改为`default`即可恢复正常。

### 6. DDNS

在使用 TP-Link 路由器时，我用的是 TP-Link 提供的 DDNS 服务（甚至是有企业备案的域名）。而在使用小米官方固件时，我用的是花生壳。但换到 QWRT 之后，花生壳 DDNS 在几次更换 IP 之后突然不会解析了，使用 3322 也在一次解析之后就不再变了，搞得我很疑惑。

这时有群友指出 QWRT 可以使用 CloudFlare 进行 DDNS 解析，而我却没找到提供商里有 CloudFlare。最后发现，QWRT 是需要安装软件包并手动编辑 DDNS 配置文件才能使用 CloudFlare DDNS 的。

据说新版 DDNS 插件支持使用受限的 API 令牌了，但我试了半天也不能用，于是还是用了全局 API 密钥，反正路由器在自己家，也不对公网开放。

CloudFlare 是真的好用，~~前面忘了后面忘了，总之 CloudFlare 为什么是神~~。

### 7. WireGuard

我是为了使用公网 WOL 而刷的 QWRT。但搞笑的是，在写好 ARP 绑定规则，配置完 DHCP 静态地址分配之后，我从公网依然不能唤醒关机超过一段时间的电脑。在我打算将路由器管理页面向公网开放，然后用后台的网络唤醒开电脑的时候，群友和我说可以使用 WireGuard 与路由器连接，直接开放不安全。

配置 WireGuard 还算简单，Google 一下就拿到了很多相关教程，照着配置了一会便成功了。

但其实我也折腾了半天，主要是因为这件事是在用 CloudFlare DDNS 之前，而原本的 DDNS 解析在多次重启路由器后已经对不上了，我还是用域名测试的 WireGuard，结果就是怎么找都找不到不对的地方，但就是连不上，手动填完公网 IP 立刻正常。

### 8. ZeroTier

因为手里有台国内小机当 N2N 节点，所以本来想搭个 N2N 作为后备手段，避免连 IP 都拿不到。但 QWRT 装不上 LuCI N2N 软件包，于是转向了 ZeroTier。

配置 ZeroTier 还算比较傻瓜式的，在 QWRT 内置的 ZeroTier 下很轻松就搭建好了，目前作为备用连接方式。

### 9. 查看已连接的设备

QWRT 似乎没有一个地方能查看所有已连接的局域网设备，有说可以从路由表看的，但我没太看明白，大概是因为我配置了 ARP 绑定吧。也有说看 DHCP 分配，但也被静态分配搞的看不了了。

我自己研究的方法有：

  1. 概览中的在线用户就是当前局域网中的设备数量。
  2. `网络→无线`下面的已连接站点可以看到所有连接到路由器的无线设备，基本可以判断谁在连 WiFi。

至于有线设备，用总设备数量减去无线连接数量就能知道了。反正我家联网设备数量我是知道的，倒也不用太在乎。

## 总结

刷路由器和刷手机一样，越刷越上头。折腾了两天，再加上这段时间断断续续的了解，现在差不多已经搞明白 QWRT 了。

搞这玩意还顺便学了一下 IPv6 的一些知识，比如局域网分配之类的，因为之前路由器不支持 IPv6，所以也就一直没了解过。了解完发现还不如不了解，乱七八糟的就让它当个增益 Buff 自己跑去吧，确认完可用性我就老老实实用我的 IPv4。

以上，就先写这些吧，等想起什么再补，~~我要接着享受酣畅淋漓的网络环境去了~~。
开学了，不在家，现在只能远程跑个 BT 之类的，但更多的也是我直接在学校跑流量下。折腾这东西也学到不少，就这样吧。
